01

构建失败，一眼定因

ArkTS 编译输出的泥潭里，真实错误只有一条，噪音却有六条。build-diagnostics 插件在输出前注入结构化诊断 —— 错误码、文件、行号，以及下一步建议。

$ [aeox 构建诊断] → [10505001] Index.ets:32:15
02

API 行为，先查再写

模型凭记忆写 ArkUI 是过时写法的重灾区。docs_search 直连鸿蒙官方文档，规则强制：不确定的 API，禁止凭记忆作答。

$ docs_search "@Builder param 传递" → docs_read …
03

修过的坑，不再重踩

每个非平凡 bug 修复后入库：症状、根因、解法。下次遇到同款报错，先查库 —— 历史结论直接复用，排查时间从小时到秒。

$ kb_add "audit_check JSON5 正则" && kb_search "带引号键"
04

上架之前，一键体检

配置完整性、敏感权限、协议页、签名材料。audit_check 输出一份可勾选的提审清单 —— 心安，是上线前最好的状态。

$ audit_check ./MyApp → 0 ERROR / 1 WARN
05

两步启用，随装随卸

一行命令装好并接线（幂等），一行命令验证。卸载只需移除链接与全局包 —— 宿主一个字节都不用改。

前置条件：Windows · Node.js ≥ 22.18 · DevEco Code（先安装并至少启动一次）。aeox-cli 是 DevEco Code 的增强外挂 —— 先有宿主才能接线；未装宿主时也能完成安装，但插件注册会被跳过，装了等于没装。
# 1. 一键安装：npm 全局安装 + junction 链接 + 插件注册（幂等）
$ iwr -useb https://cli.aeox.uk/install.ps1 | iex
#    手动等价（两条分开执行；Windows PowerShell 5.1 不支持 &&）：
$ npm install -g aeox-cli
$ aeox install
# 2. 验证：13 项体检全绿，或在会话内输入 /aeox
$ aeox doctor
