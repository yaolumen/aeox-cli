# 调试纪律

- 先稳定复现问题，再动手修改
- 读完整错误信息和堆栈，定位到根因代码行，不凭猜测打补丁
- 一次只改一处，改后立即验证因果关系
- 修根因，不修症状；禁止吞异常让报错消失
- 结论必须有证据支撑：日志、断点、构建输出，不靠"应该可以了"

# 知识库闭环

- 排查任何非平凡错误（arkts-* / 构建 / 运行时 / 提审）**先调用 kb_search**，命中则按解法处理并验证
- 未命中才从头排查；解决后**必须调用 kb_add 记录**（症状含关键报错原文 / 根因 / 解法），这是硬性约定
- 鸿蒙 API 行为不确定时，先 docs_search 查官方文档，不凭记忆作答
